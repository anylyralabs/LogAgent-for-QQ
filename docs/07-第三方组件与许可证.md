# 第三方组件与许可证

> 适用：`linux` 分支与 Android APK 分发（GPLv2，见 [LICENSE](../LICENSE)）
> 更新：2026-10-20

本项目自身代码按 **GPLv2** 发布。下面列出**随二进制分发**（尤其 APK）的第三方组件及其许可证。
如果你只是在桌面上跑 `LogAgent.Headless` 或 `LogAgent.App`，多数组件并不随之分发——以实际产物为准。

## 1. 随 Android APK 分发的原生组件

APK 里有两类原生文件：`lib/arm64-v8a/*.so`（安装后落在 `nativeLibraryDir`）与
`assets/tools/libtalloc.so.2`（首次启动解到私有目录）。清单如下。

| 文件 | 组件 | 许可证 | 来源 |
|---|---|---|---|
| `lib/arm64-v8a/libproroot.so`<br/>`-runtime.so` / `-linker.so` / `-bridge.so` / `-stub-loader.so` | [proroot](https://github.com/coderredlab/proroot) v1.2.8 | **专有（Proprietary）** | 官方 Release 二进制，允许自由使用、允许再分发未修改的二进制，**禁止分发修改版** |
| `lib/arm64-v8a/libproot.so` | [proot](https://github.com/termux/proot)（Termux 构建） | **GPLv2** | Termux 软件仓库 `proot` 包 |
| `lib/arm64-v8a/libprootloader.so` | proot 的 loader（同上包内） | **GPLv2** | 同上 |
| `lib/arm64-v8a/libandroid-shmem.so` | [termux/libandroid-shmem](https://github.com/termux/libandroid-shmem) | **MIT** | Termux 仓库 `libandroid-shmem` |
| `assets/tools/libtalloc.so.2` | [Samba talloc](https://talloc.samba.org/) 2.5.0 | **GPL-3.0-or-later**（Termux 包的 `copyright` 为 GPLv3 全文） | Termux 仓库 `libtalloc` |
| `assets/logagent.tar.gz` 内 `libe_sqlite3.so` | [SQLitePCLRaw](https://github.com/ericsink/SQLitePCLRaw) 打包的 SQLite | **Public Domain**（SQLite 本身） | NuGet `SQLitePCLRaw.lib.e_sqlite3` |
| `classes.dex` | 本项目代码 + .NET 运行时不存在于 dex | GPLv2 | 本项目 |

### 1.1 关于 proroot 的专有许可证

proroot 的许可是「允许自由使用、允许再分发未修改的二进制、**禁止分发修改版**」。
我们**未修改**这 5 个 `.so`（源码 SHA-256 见下表），因此可以随 APK 分发。

这也意味着一条硬约束：**不要 patch proroot 的二进制**。一旦需要改它，就必须换引擎。

| 文件 | SHA-256 |
|---|---|
| `libproroot.so` | `a4e74d75b66cdc02b080adfe863dbf9951c3b30610d77beddc95488d5fe5de01` |
| `libproroot-runtime.so` | `8c47a0a7db32d84c179ebb5bf3640f655a3181860ece5886ae44d92858730c34` |
| `libproroot-linker.so` | `51a0ec5bfed00e572a0de09e22d9057e2befc386b78e426613d3e0ab03f4ecee` |
| `libproroot-bridge.so` | `1c5bc9537a270e8bf8b1c70222813f57b60b828bfb5503ddf8fe37685092de2f` |
| `libproroot-stub-loader.so` | `06c6624db3bdc45b9ced151cd781df439a37b47731d244b93e9d6a58cd48cde0` |

### 1.2 GPLv2 与 GPLv3 的兼容性（必须注意）

本项目按 **GPLv2**（不含 "or later"）发布，而 `libtalloc.so.2` 是 **GPLv3**。
GPLv2-only 与 GPLv3 **不兼容**：把这两者组合成一个作品分发，在严格解释下是有冲突的。

实际情况与处理方式：

| 事实 | 说明 |
|---|---|
| 二者是**独立进程/独立可执行文件** | talloc 只被 `libproot.so` 动态加载，与我们自己的代码不构成「单一作品」（GPL FAQ 的 mere aggregation 情形） |
| talloc 只服务于 **proot 兜底路径** | 主路径是 proroot，不加载 talloc |
| 最保守的做法 | ①把本项目改为 **GPLv2-or-later**（即可合法升级到 GPLv3 组合）；或 ②APK 不打包 proot 兜底（只留 proroot） |

> **建议**：若要保持 GPLv2，建议采用 **GPL-2.0-or-later** 表述（`LICENSE` 保持 GPLv2 全文，
> 在 README 声明 "GPLv2 or later"）。这样与 GPLv3 的 talloc、以及未来任何 GPLv3 依赖都不冲突。
> 这条需要项目负责人拍板，本文档只记录事实与选项，不代为决定。

### 1.3 GPLv2 义务如何履行（proot 相关）

`libproot.so` / `libprootloader.so` 是 GPLv2 代码的二进制。按 GPLv2 §3，分发二进制时必须
提供**完整对应源码**。本项目采取 §3(a)/(b) 的方式：

- **本仓库即对应源码的一部分**（本项目的 GPLv2 代码）；
- **proot 的对应源码**：`https://github.com/termux/proot`（Termux 构建所用上游），
  以及 Termux 打包脚本 `https://github.com/termux/termux-packages/tree/master/packages/proot`；
- **talloc 的对应源码**：`https://github.com/termux/termux-packages/tree/master/packages/libtalloc`
  （上游 `https://talloc.samba.org/`），版本 2.5.0；
- 分发二进制时，需在发布页写明上述地址，或随包附上源码快照。

> 若后续决定 APK 只保留 proroot（不含 proot 兜底），可移除这两件，
> 但会失去「proroot 失败时降级」的能力，见 `docs/06-Android-APK方案-proroot容器.md` §5。

## 2. rootfs 内随 APK 分发的 Ubuntu 组件

`assets/rootfs.tar.gz` 是 **Ubuntu 24.04 base（arm64）**的最小化快照，来自
[Ubuntu Base 官方镜像](https://cdimage.ubuntu.com/ubuntu-base/releases/24.04/release/)。
Ubuntu 的许可证信息在 rootfs 内完整保留，未做删改：

```
rootfs/usr/share/doc/*/copyright   # 每个包的完整许可证与版权声明
rootfs/usr/share/common-licenses/  # GPL-2 / GPL-3 / LGPL / Apache 等全文
```

其中的核心组件（`bash`、`coreutils`、`grep`、`sed`、`dpkg`、`apt`、`gcc-14-base` 等）
多为 **GPLv2 / GPLv3 / LGPL**，其源码由 Ubuntu 官方归档提供：
`https://archive.ubuntu.com/ubuntu/pool/`（按 `apt-get source <包名>` 取对应版本）。

> 本项目**未修改** rootfs 内任何软件包；仅做了两件事：
> ①删除 apt 缓存与日志（不影响许可证文件）；
> ②注入 CA 证书与 `/etc/localtime`（前者来自 `ca-certificates` 包，后者是指向 zoneinfo 的链接）。
>
> 若你需要 rootfs 内某组件的精确源码，先在 rootfs 里 `dpkg -l` 查到版本，
> 再用 `apt-get source <包名>=<版本>` 获取。

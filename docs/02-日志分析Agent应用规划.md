# logagent-for-qq —— 日志分析 Agent 应用规划

> 版本：v0.3（2026-10-15，新增：沙箱执行环境——文件管理/上传下载/Shell）｜ 技术栈：C# 桌面应用｜ 本文档基于《01-Agent应用构建工作流-学习笔记.md》的模式结论

## 1. 项目定位

一个**本地优先**的 C# 桌面 Agent 应用，以 QQ 为交互入口，提供：

1. **QQ 群上下文智能分析**——理解群聊语境，回答技术问题、关联历史讨论；
2. **日志智能分析**——接收/抓取日志文件，自动解析、定位异常、给出根因推断；
3. **自助学习能力**——从用户回答中积累经验 + 主动访问网站获取新知识，越用越懂行；
4. **知识库与记忆管理**——可管理、可检索、可淘汰的分层记忆体系；
5. **双协议接入**——QQ 官方机器人 + OneBot11（NapCat），由我方全权管理 NapCat（扫码登录、后台管理）；
6. **多模型分流**——按任务类型路由不同 LLM，含健康检查与故障切换，提高整体可用性。

└──────────┬──────────────────────────┬───────────────────────┘

**设计原则**（来自学习笔记）：

- 从 workflow 起步，只在该自主的地方用 agent 循环；
- 每条消息的处理路径可配置、可观测、可回放；
- 所有 LLM 调用经过路由器，统一计量、统一熔断。

## 3. 模块设计

### 3.1 连接层（双协议适配）

#### A. OneBot11 / NapCat 适配器

- **通信模式**：首选**反向 WebSocket**——我们的应用起 WS Server（如 `ws://127.0.0.1:6701/onebot/v11/ws`），NapCat 作为客户端主动连入，心跳 30s、断线重连 30s、Token 鉴权。备用：正向 WS / HTTP Webhook。
- **NapCat 托管管理**（我方全权负责）：
  - **进程管理**：检测/下载/启动/停止 NapCat（Shell 版），固定 `machine-id` 防风控；
  - **扫码登录**：对接 NapCat WebUI（默认 6099 端口）API，把二维码实时投到桌面应用 UI 上，扫码成功后持久化快速登录凭据；
  - **后台管理**：UI 内可视化编辑 `onebot11.json`（连接地址/Token/心跳）、查看 NapCat 运行日志、重连状态；
  - **风控注意**：使用有正常使用记录的 QQ 号；避免频繁扫码/换设备；WebUI 不暴露公网。
- **消息规范**：统一 OneBot11 事件模型（群消息/私聊/通知），消息段（CQ 码）解析为内部统一 `BotMessage`。

#### B. QQ 官方机器人适配器

- **接入**：QQ 开放平台（`api.bot.qq.com`），WebSocket 接收事件（`GROUP_AT_MESSAGE_CREATE` / `C2C_MESSAGE_CREATE`）+ HTTPS OpenAPI 发送。
- **关键限制（必须在适配器内消化）**：
  - 群聊**被动回复**需携带 `msg_id`，有效期 **5 分钟**、每条消息限回 **5 次**；
  - 主动消息受用户开关限制，按周期限量；
  - 全局 800 次/分钟限频 → 适配器内置令牌桶。
- **抽象**：两个适配器实现同一 `IBotConnection` 接口（收消息/发消息/撤回/上传文件），Agent 核心对协议无感知。

### 3.2 Agent 核心

| Agent            | 模式                        | 职责                                                         |
| ---------------- | ------------------------- | ---------------------------------------------------------- |
| **群上下文分析 Agent** | ReAct                     | 理解群聊语境；决定何时接话（@触发/关键词/静默）；带情景记忆回答                          |
| **日志分析 Agent**   | Plan-Execute + Reflection | 接收日志 → 制定分析计划（解析→统计→异常识别→检索知识库→根因推断）→ 逐步执行 → 反思校验结论 → 产出报告 |
| **学习 Agent**     | Reflection                | 处理"未知问题"：整理用户回答/网页抓取结果 → 去噪提炼 → 写入知识库候选区                   |

- **框架**：Microsoft Agent Framework（编排、中间件 guardrails）+ Semantic Kernel（插件、prompt 模板、记忆连接器）。
- **工具集**（SK 插件，每个 3–7 个函数）：
  - `LogTools`：解析（多格式：纯文本/JSON/log4j/自定义正则）、按级别过滤、时间窗切片、异常聚类；
  - `KnowledgeTools`：知识库检索（混合检索：向量+关键词）、写入候选知识；
  - `WebTools`：网页抓取（HtmlAgilityPack）、正文提取、搜索（接搜索引擎 API）；
  - `GroupTools`：查询群历史消息（情景记忆检索）、群成员信息；
  - `SandboxTools`：沙箱内文件管理（列/读写/移动/删除/解压）、URL 下载、白名单 Shell 执行（详见 3.9）；
  - `ReportTools`：生成分析报告（文本/图片渲染，走 QQ 富媒体发送）。
- **Guardrails（中间件）**：迭代上限（如 8 步）、token 预算、耗时上限、敏感操作（删知识、群发）人工确认。

### 3.3 记忆管理（三层）与会话生命周期

| 层    | 实现                        | 内容                            |
| ---- | ------------------------- | ----------------------------- |
| 工作记忆 | 会话上下文窗口（带淘汰/滚动摘要）         | 当前群消息流、当前分析任务的 ReAct 轨迹       |
| 情景记忆 | SQLite + 向量索引（sqlite-vec） | 群历史摘要（每群每日/每周滚动摘要）、历史问答对、用户偏好 |
| 语义记忆 | 知识库（RAG）                  | 日志模式库、错误码字典、产品文档、历史分析报告       |

#### 3.3.1 会话模型（Session）

每个 chat（群/私聊/官方 Bot 会话）维护一个**活跃会话**：

```
Session {
  Id, ChatId, StartTime, EndTime, CutReason,
  Turns[]        // 一次完整问答 = 用户输入 + 检索上下文 + Agent回答 + 轨迹摘要 + 反馈标签
  RawMessages[]  // 原始消息流（L0，永不丢弃）
  Summary        // L1 会话摘要
  KeyFacts[]     // L2 结构化关键事实
  TokenStats     // 累计 token 计量
}
```

#### 3.3.2 会话切断（Session Cut）

任一规则命中即切段，开启新会话（**切断 ≠ 丢弃**，旧会话原文全量归档）：

| 规则   | 默认值               | 说明                              |
| ---- | ----------------- | ------------------------------- |
| 超时切断 | 静默 30 分钟          | 群里没动静，话题自然结束                    |
| 语义切断 | 相似度 < 阈值          | 新消息与近期窗口 embedding 相似度骤降 → 话题切换 |
| 容量切断 | token > 8k 或消息数超限 | 防上下文膨胀，强制切段                     |
| 手动切断 | 命令 / UI           | 群内 `@机器人 新话题` 或管理后台手动切段         |
| 事件切断 | 任务边界              | 日志分析任务完成即自然成段（任务型会话）            |

#### 3.3.3 分级压缩（Compression）

```
L0 原文（全量保存，训练数据原料）
   └─→ L1 摘要：切段时用便宜模型生成（做了什么/结论/关键实体）→ 情景记忆
         └─→ L2 关键事实：结构化抽取（用户偏好、结论、错误模式）→ 语义记忆候选
```

- **工作窗口只装**：最近 N 条 L0 原文 + 本会话 L1 摘要 + 检索命中的 L1/L2；
- 摘要/抽取走模型路由器（低成本模型），失败可重试，不影响主流程；
- 每个会话的压缩产物与原文关联存储，可追溯"这段摘要从哪来"。
- **群上下文策略**：新消息进来 → 滑动窗口保留最近 N 条原文 + 加载该群摘要 + 检索相关历史问答；每日凌晨为活跃群生成滚动摘要。
- **驱逐与边界**：情景记忆按群设置容量上限；摘要任务用便宜模型；防上下文污染（无关检索结果过滤阈值）。

### 3.4 知识库管理（RAG）

- **存储**：本地优先——SQLite（元数据+FTS5 关键词索引）+ sqlite-vec（向量）；预留 Qdrant 适配接口供规模化。
- **管道**：文档/网页/用户回答 → 清洗分块（按结构+语义）→ Embedding（走模型路由器，可用低成本 embedding 模型）→ 入库（状态=候选）。
- **检索**：混合检索（向量 top-k + FTS5 关键词），Rerank 后注入上下文，附引用来源。
- **管理 UI**：条目浏览/编辑/删除、来源标记（用户回答/网页/手动）、候选区审核（学习 Agent 产出的知识需人工或 Reflection 通过后转正）。

### 3.5 自学习管道

```
未知问题（Agent 无法回答/置信度低）
   ├─→ 路径A：向群友提问 → 用户回答 → 学习Agent提炼（Reflection去噪）→ 知识库候选区
   └─→ 路径B：WebTools 搜索+抓取相关网页 → 学习Agent提炼 → 知识库候选区
                                    ↓
                    候选审核（人工确认 或 自动评分>阈值）→ 转正入库
                                    ↓
                    下次同类问题 → RAG 检索命中 → 带引用回答
```

- **闭环可观测**：记录"哪条知识被用来回答了哪个问题、用户后续是否纠正"，形成知识质量反馈，低分知识自动降权/进淘汰队列。

### 3.6 多模型分流路由器

```
请求 → 任务分类（规则+轻量模型：聊天/日志分析/深度推理/摘要/Embedding/图片）
     → 模型策略表（每类任务：首选模型 + 备选链 + 参数预算）
     → 健康检查（熔断器：错误率/延迟）→ 命中故障自动切换备选
     → 统一计量（token 用量/成本/延迟，按群、按 Agent 归集）
```

- 所有 provider 走 **OpenAI 兼容接口**（一个 `IChatClient` 抽象 + provider 配置：API 地址/密钥/模型名）；
- 可配置降级策略：日志分析优先质量（大模型），群闲聊优先延迟（小模型），摘要/Embedding 用便宜模型；
- UI 实时看板：各模型健康状态、成本曲线、失败率。

### 3.7 UI（WPF 管理后台）

页面：① 仪表盘（连接状态/消息量/模型健康）② NapCat 管理（扫码登录、配置、日志终端）③ 知识库管理 ④ 记忆浏览器（按群查看摘要/历史）⑤ **会话管理**（会话列表/切段预览/手动切断/查看压缩层级/导出训练数据）⑥ 模型路由配置 ⑦ 分析报告归档 ⑧ **沙箱管理**（工作区浏览/命令审计日志/白名单配置）⑨ 设置（触发规则/权限/风控）。

### 3.8 会话数据与训练导出管道（为将来训练模型储备数据）

**目标**：日常运行沉淀的会话数据，经过清洗、脱敏、标注后，可直接作为微调/偏好训练的数据集。

**存储**：会话库（SQLite：`sessions` / `raw_messages` / `turns` / `summaries` 表）。`Turn` 是训练的基本单元——一次完整问答及其完整上下文（检索命中、Agent 推理轨迹、最终回答、用户反馈）。

**质量标签**（每个 Turn 自动打标，导出时按标签筛选）：

| 标签    | 判定               | 训练用途                |
| ----- | ---------------- | ------------------- |
| 采纳    | 用户继续对话/正面反馈/长按点赞 | SFT 正样本             |
| 无反馈   | 无后续信号            | 默认排除或低权重            |
| 被纠正   | 用户指出错误/追问推翻结论    | DPO 偏好对的 rejected 侧 |
| 修正后采纳 | 纠正后 Agent 给出正确答案 | SFT + DPO chosen 侧  |

**导出格式**（一键导出到本地目录，JSONL）：

- **OpenAI Chat**（`{"messages": [...]}`，SFT 通用）；
- **ShareGPT**（多轮对话格式）；
- **Alpaca**（instruction/input/output 单轮）；
- **DPO 对**（`{"prompt", "chosen", "rejected"}`）；
- 元数据字段：`source`（群聊/日志分析/私聊）、`session_id`、`quality`、`timestamp`、`model_used`。

**脱敏（导出前强制）**：QQ 号→`<QQ_占位>`、内网 IP/URL/密钥模式→正则替换占位符；白名单可配；**导出动作本身在 UI 留审计记录**。

**闭环**：导出的数据集可回灌 M5 的评估集——微调后的模型用同一批会话问题做回归对比，量化"自产数据训练"的收益。

### 3.9 沙箱执行环境（文件管理 + 上传下载 + Shell）

**动机**：日志分析天然要和文件打交道——群里发来的日志压缩包要解压、远程 URL 的日志要下载、大文件统计要用 shell 命令（grep/awk/排序去重）在本地算而不是烧 LLM token。但 **LLM 生成的操作绝不能直接碰真实文件系统**，需要一层受控沙箱。

#### 沙箱边界

- **独立工作区**：每个任务分配临时工作目录（`%AppData%/LogAgent/sandbox/{taskId}/`），任务结束随会话归档或按策略清理；
- **文件操作限定沙箱内**：所有路径先规范化再校验——解析后的绝对路径必须在沙箱根目录之下，拦截 `..` 穿越、symlink 逃逸、盘符绝对路径；
- **进程隔离**：shell 子进程挂 Windows **Job Object**（控制进程树、CPU/内存/时长配额，超时整树强杀）；Linux 用进程组 + `Process.Kill(entireProcessTree: true)`（读 `/proc` 杀整棵树），进阶可升级 cgroup v2 或容器化；
- **平台适配**：shell 入口由 `LogAgent.Shared/Platform` 的 `IShell` 决定——Windows `cmd.exe /c chcp 65001 & 命令`，Linux/macOS `/bin/sh -c 命令`（可用 `LOGAGENT_SHELL` 覆盖）；白名单/黑名单按平台生成默认值，`run_shell` 的提示词示例也随平台变化；
- **网络只放行下载**：仅 http(s) GET、大小上限、超时控制、扩展名/MIME 白名单。

#### 能力矩阵

| 能力    | 说明                         | 安全约束                       |
| ----- | -------------------------- | -------------------------- |
| 文件管理  | 列目录/读写/移动/删除/解压（zip/gz/7z） | 限定沙箱内；删除需确认策略；全部审计         |
| 下载    | URL → 沙箱文件（拉取远程日志、学习资料落盘）  | 仅 http(s)；大小/超时上限；类型白名单    |
| 上传    | QQ 群文件/图片自动落沙箱；UI 手动导入     | 类型白名单；预留病毒扫描接口             |
| Shell | 执行命令并返回输出                  | 白名单优先；超时杀进程树；输出截断；cwd 锁定沙箱 |

#### Shell 安全（LLM 生成命令 = 注入高危面）

- **白名单优先**：预置安全命令集（grep/sed/awk/wc/sort/uniq/head/tail/find/解压工具/受控 python 脚本），默认只允许白名单内命令与参数模式；
- **黑名单兜底**：破坏性模式拦截（`rm -rf`、格式化、注册表、计划任务、账户操作、凭据读取等正则集）；
- **审计**：每条命令执行前先落审计日志（任务/Agent/命令原文/退出码/耗时），UI 沙箱管理页可查；
- **人工确认**：高危操作（新增出网目标、批量删除）走 guardrails 中间件的人工确认机制（复用 3.2）；
- **输出回灌保护**：命令输出超过阈值（如 32KB）截断，二进制输出直接转文件引用，不进 LLM 上下文。

#### 与既有模块的协同

- **日志分析 Agent**："本地统计降采样"步骤真正落地之处——大文件用 grep/awk 在沙箱聚合，只把统计结果喂 LLM（M3 的 token 控制依赖它）；
- **学习 Agent**：网页抓取的资料先落沙箱，清洗后再进知识库分块管道；
- **会话/归档**：沙箱工作区随任务归档，分析报告引用的中间产物（错误样本、统计快照）可追溯。

**工具插件**：`SandboxTools`（list_files / read_file / write_file / move / delete / extract_archive / download_url / import_file / run_command），注册给日志分析 Agent 与学习 Agent。

## 4. 技术选型汇总

| 层        | 选型                                          | 理由                     |
| -------- | ------------------------------------------- | ---------------------- |
| 运行时      | .NET 8 (LTS)                                | 长期支持，C# 桌面首选           |
| UI       | WPF + CommunityToolkit.Mvvm                 | 成熟、资料多、好维护             |
| Agent 框架 | Microsoft Agent Framework + Semantic Kernel | 微软官方战略方向，C# 原生，MCP 支持  |
| 模型接入     | OpenAI 兼容 `IChatClient` 抽象                  | 一套代码接任意 provider       |
| 协议       | 自研 OneBot11 适配器（WebSocket）+ 官方 Bot SDK 封装   | 双协议统一 `ChannelManager` + `IBotConnection` |
| 存储       | SQLite + FTS5 + sqlite-vec                  | 单文件零运维，本地优先；向量+关键词混合检索 |
| 网页抓取     | HtmlAgilityPack + 正文提取                      | 学习 Agent 的 WebTools 底座 |
| 日志解析     | Serilog（应用日志）+ 自研规则解析器                      | 支持多格式 + 自定义正则          |
| 可观测      | OpenTelemetry + 本地 trace 存储（SQLite）         | 每步 Agent 轨迹可回放         |

## 5. 关键流程示例：日志分析（端到端）

1. 用户在群里 `@机器人 分析日志` + 附件（或粘贴文本/文件链接）；
2. 连接层解析为统一消息 → 路由到日志分析 Agent；
3. **Plan**：制定计划（识别格式 → 切片统计 → 提取异常簇 → 检索知识库相似案例 → 根因推断 → 生成报告）；
4. **Execute（ReAct 每步）**：调用 LogTools/KnowledgeTools；大文件先本地统计降采样，只把关键行喂给 LLM（控 token）；
5. **Reflect**：结论自检（是否每个异常都有证据行支撑？是否与检索到的历史案例矛盾？）；
6. 报告发送（文本摘要 + 可选图片详报）；本次分析全文入"分析报告归档"→ 语义记忆；
7. 若用户追问/纠正 → 触发学习管道。

## 7. 风险与对策

| 风险                     | 对策                                                        |
| ---------------------- | --------------------------------------------------------- |
| NapCat/QQ 个人号风控        | 用养过的号；固定 machine-id；不频繁扫码；WebUI 不暴露公网；同时保留官方 Bot 通道作为合规备份 |
| 官方 Bot 群聊被动回复 5 分钟窗口（主动消息需群主开启） | 窗口内合并回复；超时/超次数自动降级主动消息，群聊主动消息依赖群主设置 |
| 大日志文件 token 爆炸         | 本地优先统计降采样；只送异常簇关键行；超长报告转图片/文件                             |
| 自学习引入错误知识              | 候选区+审核机制；知识质量反馈分；可回滚（知识条目带来源和版本）                          |
| 单模型服务不可用               | 路由器熔断+备选链；多 provider 配置；健康探测                              |
| 上下文污染/记忆膨胀             | 检索相关度阈值；群级容量上限与驱逐策略；摘要用便宜模型                               |
| 训练数据隐私泄露               | 导出前强制脱敏（QQ号/IP/密钥正则替换）；导出审计日志；群主可配置"本群不入训练集"              |
